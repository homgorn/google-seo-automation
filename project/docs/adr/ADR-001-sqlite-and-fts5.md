# ADR-001: SQLite + FTS5 как основное хранилище вики

- **Статус:** принято
- **Дата:** 2026-10-12
- **Решает:** где хранить документацию Google API и как искать по ней

## Контекст

Нужно хранить ~312 эндпоинтов из 8 Google API, искать по ним текстом и
семантически, отслеживать изменения, и всё это без внешней инфраструктуры —
чтобы репозиторий оставался самодостаточным и клонировался одной командой.

Кандидаты: PostgreSQL + pgvector, Elasticsearch, ChromaDB, SQLite + FTS5,
plain-файлы + ripgrep.

## Решение

**SQLite + FTS5** как основное хранилище. ChromaDB — опциональное
дополнение для семантического поиска, не замена.

## Обоснование

| Критерий | SQLite+FTS5 | ChromaDB | Postgres+pgvector | Elasticsearch |
|----------|-------------|----------|-------------------|---------------|
| Зависимости | 0 (stdlib) | ~2GB (torch) | сервер | сервер |
| FTS из коробки | ✅ FTS5 | ❌ | ❌ (нужна pg_trgm/tsvector) | ✅ |
| Векторный поиск | ❌ | ✅ | ✅ | ✅ |
| Транзакции | ✅ | ❌ | ✅ | ❌ |
| Один файл = вся БД | ✅ | каталог | сервер | кластер |
| Порог входа | нулевой | pip install | docker | docker |

FTS5 даёт полнотекстовый поиск с релевантностью BM25, триггерами
синхронизации и подсветкой — без единой внешней зависимости. Порог входа
критичен: вся ценность проекта в том, что `git clone` + `init.sh` дают
рабочую базу.

## Последствия

**Плюсы**
- `sync_wiki.py` и `wiki_query.py` работают на стандартной библиотеке
- БД — переносимый файл, можно коммитить или копировать
- Нет отдельного процесса в CI
- Транзакции: синхронизация атомарна

**Минусы**
- Векторный поиск требует chromadb (опционально, с graceful fallback)
- Нет параллельной записи из нескольких процессов (SQLite сериализует)
- Одна БД на диске — не масштабируется горизонтально

## Когда пересматривать

- Объём документации >10k документов И нужен векторный поиск по умолчанию
- Появилась потребность в нескольких писателях в БД одновременно
- Нужны сложные JOIN-запросы по метаданным API
