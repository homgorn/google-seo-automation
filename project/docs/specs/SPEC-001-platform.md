# SPEC-001 — Платформа Google SEO Automation

## 1. Назначение

Единая платформа автоматизации Google-сервисов продвижения: измерение
(GA4), развёртывание тегов (GTM), органический поиск (Search Console),
платный поиск (Google Ads), локальный поиск (Business Profile), скорость
(PageSpeed) и видимость в AI-ответах (AEO / AI Overviews).

Платформа построена вокруг **внутренней вики-базы**, которая сама
обновляется из официальных машиночитаемых источников Google
(Discovery Documents) и является единственным источником правды об API.

## 2. Не-цели (Non-goals)

| # | Не делаем | Почему |
|---|-----------|--------|
| 1 | Не строим собственный веб-аналитический трекер | GA4 уже это делает, и хуже |
| 2 | Не заменяем Search Console / GTM UI | Автоматизация — для рутины и отчётности |
| 3 | Не делаем pSEO-генерацию страниц | Отдельная задача, другой проект |
| 4 | Не пишем свой LLM-раннер | Используем готовые инструменты |
| 5 | Не храним сырые события GA4 | BigQuery — правильное место для этого |

## 3. Архитектурные принципы

### P1 — Единый источник правды об API
Все скрипты **не ходят в сеть за документацией**. Единственная точка входа —
`sync_wiki.py`. Это даёт одну точку отказа, один журнал изменений и один
счётчик свежести.

### P2 — Деривативность
БД (`data/wiki.db`) — кэш. Она восстанавливается из источников одной
командой. Поэтому её можно удалять без потери данных.

### P3 — Dry-run по умолчанию
Любая мутация внешнего состояния (создание кампании, публикация версии
GTM, отправка URL в Indexing API) требует явного разрешения:
`ALLOW_MUTATIONS=1` + `dry_run=False`.

### P4 — Безопасность по умолчанию
- Секреты только из окружения, никогда не в коде и не в логах.
- Бюджеты Google Ads — в микросах, с потолком `ADS_MAX_MUTATION_MICROS`.
- Кампании создаются в статусе `PAUSED`; активация — только после
  подтверждения человека.
- Indexing API: жёсткий лимит 200 запросов/день.

### P5 — Измеримость каждого шага
Каждая фича имеет список шагов в `feature_list.json`. Шаг проверяем
литерально — как это сделал бы человек, а не «код выглядит правильно».

### P6 — Факты, а не догадки
Все утверждения о поведении API помечены provenance:
`[измерено]` / `[сообщено: URL + дата]` / `[выведено]`.

## 4. Компоненты

```
┌──────────────────────────────────────────────────────────────┐
│ L4  Потребление                                              │
│     • CLI (wiki_query, verify_feature, secret_scan)         │
│     • OpenChamber-сессии, cron-расписания                    │
├──────────────────────────────────────────────────────────────┤
│ L3  Автоматизации                                             │
│     ga4 / gtm / gsc / ads / aeo / openchamber_sync           │
├──────────────────────────────────────────────────────────────┤
│ L2  Знание                                                    │
│     • SQLite: api_docs, api_endpoints, schemas, guides       │
│     • change_log, sync_runs, embeddings, aeo_citations        │
│     • FTS5 (полнотекст) + wiki/_data (граф знаний)           │
├──────────────────────────────────────────────────────────────┤
│ L1  Источники                                                 │
│     • Google Discovery Documents (8 источников)              │
│     • Локальные wiki/*.md (markdown-истина)                  │
└──────────────────────────────────────────────────────────────┘
```

## 5. Контракты слоёв

| Контракт | Нарушение = баг |
|----------|-----------------|
| L3 → L2: чтение вики вместо сети | Дублирование документации, рассинхрон |
| L2 → L1: только `sync_wiki.py` ходит в сеть | Нет контроля свежести |
| L3 → внешний API: `dry_run=True` по умолчанию | Непреднамеренные расходы |
| L3 → БД: запись в `guides` | Потеря следов аудита |
| Любой слой → секреты: только `os.getenv` | Утечка credentials |

## 6. Требования (traceable)

| ID | Требование | Проверка |
|----|-----------|----------|
| R-01 | Вики содержит ≥300 эндпоинтов из ≥7 Google API | `wiki_query.py stats` |
| R-02 | Поиск по вике работает без внешних зависимостей | `wiki_query.py search` |
| R-03 | Изменения документов фиксируются в `change_log` | `wiki_query.py changes` |
| R-04 | Источник старше 14 дней помечается устаревшим | `sync_wiki.py --check-freshness` |
| R-05 | Каждая фича имеет ≥5 проверяемых шагов | `feature_list.json` |
| R-06 | Мутации без `ALLOW_MUTATIONS=1` не выполняются | Код + тест |
| R-07 | Бюджеты Ads проверяются на микросы | `ads_automation.py --step S01` |
| R-08 | Кампании создаются только в `PAUSED` | `ads_automation.py --step S02` |
| R-09 | Секреты не попадают в репозиторий | `secret_scan.py` + CI |
| R-10 | Wiki-индексы генерируются скриптом, не руками | `wiki_index.py --verify` |
| R-11 | Тесты покрывают все скрипты проекта | `pytest --cov` |
| R-12 | Каждая фича верифицирована агентом-verifier | `verify_feature.py --all` |

## 8. Критерии приёмки (Definition of Done)

Фича считается завершённой, когда:

1. Все шаги из `feature_list.json` выполнены и проверены
2. `pytest` зелёный, покрытие нового кода ≥ 80%
3. `secret_scan.py` чист
4. `verify_feature.py --feature FXXX` даёт PASS
5. `docs/progress.md` обновлён записью
6. `feature_list.json`: `passes: true` выставлен **только** verifier
7. Изменения закоммичены и запушены

## 9. Известные ограничения

| Ограничение | Влияние | Обходной путь |
|-------------|----------|---------------|
| Merchant API v1 не публикует discovery-методы | 0 эндпоинтов | Proto-файлы из `googleapis` |
| Bing Ads v13 — нет discovery | Нет авто-захвата | SOAP/REST вручную |
| Google Ads v18 — нет discovery | GAQL только из документации | Ручной словарь полей |
| GA4 сэмплирует >10M событий | Неточные отчёты | BigQuery export |
| GSC отдаёт 2–3 дня задержки | «Вчера» недоступно | Запрашивать за 3+ дня |
